# M06 场景需求

## 模块定位

把用户痛点落成具体场景与需求。通过用户故事描述谁在什么场景下要完成什么，并对收敛后的需求做风险标注。

## 内容结构

核心场景：产品主要使用场景，说明该场景下用户要完成什么、产品如何满足。

用户故事总览：用表格列出故事编号、用户角色、故事标题。

用户故事详情：逐条展开，每条包含用户角色、使用场景、用户故事主体（作为某角色，希望做某事，以便达成某结果）、验收标准。验收标准覆盖正常路径与异常路径。

需求清单：从场景与故事中提炼的产品需求，对存在问题但非核心的需求标注为风险需求并说明原因。

## 填写要求

- 用户故事的验收标准必须包含异常与边界，不只写成功路径。
- 需求经过收敛筛查：是否真对应用户需求、是否真解决痛点、是否真能落地。
- 风险需求标注原因。

## 质检要点

- 故事是否与 M05 的角色和痛点对得上。
- 验收标准是否覆盖异常。
- 风险需求是否标注、是否说明原因。
