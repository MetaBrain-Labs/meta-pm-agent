# 区分对话用户与目标用户(distinguish-user)
## 区分角色
+ **对话用户**：正在和你交流的这个人。
+ **目标用户**：产品最终的使用者。

这两者通常不是同一个人。常见的错配：

+ 创业者描述他想象的客户需求。
+ 管理者描述他希望员工的工作方式。
+ 产品经理转述其他部门、用户的需求。

## 识别方法
询问对话用户："你自己会用这个产品吗？如果不会，你最近一次和真实目标用户聊他们的实际工作流程是什么时候？他们当时是怎么描述的？"

然后根据回答分三种处理:

1. 对话用户 = 目标用户：可以信任他对使用场景的描述,但仍需对"用户"  
这个群体的多样性保持警惕(他只是其中一个样本)。
2. 对话者最近接触过真实目标用户：他的描述是"二手信息"，可信度  
中等，需要追问具体场景(谁、什么时候、什么情境下说的)。
3. 对话用户从未接触过真实目标用户：他描述的是"假想的用户"。这种情况下，产品草案中的用户痛点和需求章节必须标注为“假设”，并提示对话用户在产品落地前须做用户访谈验证。

仅识别一次，不需要反复询问，但识别结果要影响整个对话的可信度判断。
