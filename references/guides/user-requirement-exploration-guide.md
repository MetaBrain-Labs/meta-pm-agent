# 用户需求发散指南(user-needs-exploration-guide)
## 基础指南
本指南列出的发散点是内部检查表，不是给用户的提问清单，发散的目的是在扩大产品需求、找到有价值的产品需求分支的同时，尽可能减小用户负担，仅做定向用户追问，而不是做问卷调查。

发散可以按下述流程进行：

1. **先自答,再发问**  
每个发散点,先尝试基于对话上下文和先验知识自己回答。  
能回答的,作为"假设"输出给用户,让用户判断是否修正。  
不能回答的,才进入下一步。
2. **不能回答的,先评估"必须性"**  
不是所有不能回答的都要问。判断标准:
    - 这个问题的答案是否影响产品方向?(影响小,先用默认值)
    - 不同答案是否导致显著不同的设计?(差异小,先选常见的)
    - 现在不问,后续是否还有机会问?(后续能问,延后)  
只有"影响大、差异大、后续没机会"的才必须问。
3. **必须问的,一次最多 3 个**  
不超过 3 个追问,超过的拆到下一轮。
4. **每个问题必须带"为什么问"**  
明确问题的答案会影响产品的什么决策。  
不带原因的问题,用户答得敷衍,等于没问。
5. **优先用"假设确认"代替"开放追问"**  
"你的产品是 B 端还是 C 端?" → 开放追问,用户要思考  
"我假设这是 B 端协作产品,因为你提到了'部门'和'审批'。  
如果不对告诉我。" → 假设确认,用户只需判断对错

## 常见发散
| 发散点 | 核心问题 | 可能产出的产品需求 |
| --- | --- | --- |
| 用户角色 | 谁用、谁看、谁负责 | 角色权限、管理视图、操作记录 |
| 使用场景 | 什么时候、在哪里用 | 移动端、快捷入口、通知 |
| 任务目标 | 用户真正要完成什么 | 报告、导出、分享、审批 |
| 流程前后 | 前一步和后一步是什么 | 预填、草稿、结果页、下一步操作 |
| 痛点强度 | 高频还是高损失 | 优化交互、风控、核心能力 |
| 替代方案 | 现在怎么绕过去 | 导入导出、截图、同步、人工审核 |
| 信息输入 | 用户需要提供什么 | 默认值、校验、模板 |
| 结果输出 | 结果给谁、怎么用 | 文件、链接、版本、通知 |
| 协作关系 | 是否多人参与 | 分配、评论、审批、状态 |
| 权限责任 | 谁能做、谁负责 | 权限、日志、撤销 |
| 异常状态 | 失败和边界怎么处理 | 重试、空状态、冲突提示 |
| 频率批量 | 单次还是重复处理 | 批量操作、常用模板 |
| 配置差异 | 不同团队是否不同 | 字段配置、规则配置 |
| 数据连接 | 数据从哪来、到哪去 | 导入、同步、接口 |
| 触发机制 | 用户何时知道要处理 | 提醒、待办、订阅 |
| 成功标准 | 怎么判断有效 | 指标统计、效果评估 |
| 业务边界 | 该不该产品化 | 产品化、人工、运营、暂缓 |
